# Agent notes

Cloudflare-native rewrite of Sigfox Platform: one Worker serves a Hono API (`/api/*`) and a React SPA.
The old stack lives in `legacy/` for reference only; do not modify it.

## Layout
- `src/worker/` Hono app and D1 access (drizzle schema in `src/worker/db/schema.ts`)
- `src/web/` React SPA (TanStack Router + Query), i18n dictionaries in `src/web/i18n/`, Geist tokens in `src/web/styles/tokens.css`
- `shared/` Zod contracts imported by both sides as `#shared/<name>`; Biome forbids worker/web imports there
- `migrations/` D1 migrations generated by drizzle-kit; `test/worker/` runs on workerd, `test/web/` on happy-dom

## Commands
- `npm install && npm rebuild workerd esbuild --ignore-scripts=false` (npm runs with ignore-scripts here)
- `npm run dev` (`cf dev`): API + SPA with HMR, local state in `.cloudflare/state`
- `npm test` (`vitest run`), `npm run typecheck`, `npm run lint`, `npm run format`
- `scripts/check`: everything CI runs (install, Biome, types, tests, wrangler.jsonc drift). Must pass before a PR.
- Migrations: edit the schema, `npm run db:generate`, then `npm run db:migrate:local` before `cf dev`

## Gotchas
- Use `cf`, not `wrangler`. Config lives in `cloudflare.config.ts`.
- `wrangler.jsonc` is generated for the Deploy to Cloudflare button only. Change `cloudflare.config.ts`, then `npm run gen:wrangler`.
- Vitest config lives in `vite.config.ts` (`process.env.VITEST` switches to the workerd test pool); there is no `vitest.config.*`.
- `cf d1 migrations` takes the placeholder database id (see `LOCAL_D1_ID`), not a name, and needs `--persist-to .cloudflare/state` or `cf dev` will not see the tables.
- Runtime types for `Env` are generated into `.cloudflare/types` by `npx cf workers types` (scripts/check does this).

## Auth
- `/api/*` requires a Cloudflare Access JWT (`Cf-Access-Jwt-Assertion`), verified against `ACCESS_TEAM_DOMAIN` + `ACCESS_AUD`. `/api/health` is public; `/api/callbacks/*` takes `Authorization: Bearer sfp_…` API tokens instead.
- Local dev: copy `.dev.vars.example` to `.dev.vars` (`AUTH_DEV_BYPASS=1`; `cloudflare.config.ts` declares it only outside production, and only declared secrets get `.dev.vars` values). The bypass works only with no Access vars set and a loopback host; anything else fails closed (see `src/worker/auth/access.ts`).
- Tests inject a local JWKS through `createApp({ accessKeys })`; never fetch real Access certs in tests.

## Retention
- Daily Cron (`0 3 * * *` UTC) runs `src/worker/services/retention.ts`: deletes messages with `time < now - RETENTION_DAYS` (a row exactly at the cutoff is kept), in 1000-row batches, at most 40 statements per run; a backlog drains over several runs. Devices are never deleted.
- `RETENTION_DAYS` is a plain var in `cloudflare.config.ts` (default `"365"`, `"0"` = keep forever, invalid = log and skip). Not a secret, so `.dev.vars` does not override it.
- New time-series tables (e.g. locations) join the purge by adding an entry to `PURGE_TARGETS`.
- Trigger locally: `cf dev`, then `POST /cdn-cgi/local/explorer/api/local/scheduled`; in tests call `worker.scheduled(createScheduledController(...), env)`.
